## 📋 2. Mandated Agent Workflow Protocols (HOW)

### 2.0 Mandatory Zero-Scan Bootstrap Protocol (Universal Rule 21 / Boot Requirement)
Upon starting any new session or task, the incoming AI Agent MUST immediately load [`memory.md`](file:///c:/Users/Atul%20Verma/Desktop/AI%20Document/Interactive%20Cursor-Tracking%20Portfolio/memory.md) as its active working memory. Blind recursive workspace searches (`dir /s`, `find_files`, `grep` over the whole repo) are strictly prohibited. The agent must rely on the file map, module breakdown, and quick entry points in [`memory.md`](file:///c:/Users/Atul%20Verma/Desktop/AI%20Document/Interactive%20Cursor-Tracking%20Portfolio/memory.md).

### 2.1 CEO / Manager Delegation Model (Universal Rule 1)
- The Main Agent operates strictly as the **CEO / Orchestrator**.
- The CEO never modifies application code or runs terminal build/test commands directly when subagents can be dispatched.
- Multi-file tasks must be broken down and assigned to scoped, language-specialized subagents (`invoke_subagent`).
- Every completed subagent execution must be validated by an independent QA/verification subagent before final reporting.

### 2.2 Autonomous Forward Momentum (Universal Rule 7)
- Proceed autonomously without interrupting the user for routine confirmations (file creation, dependency checks, git logging, test runs).
- Maintain forward momentum until the objective is completely fulfilled, verified, and logged.

### 2.3 Changes Log Management (Universal Rule 6)
Every single change to repository files must be logged with full forensic diffs across:
- `changes_log/summary/changes_summary.md` (Master summary table)
- `changes_log/master/master_changes_log.md` (Deep-linked index)
- `changes_log/daily/YYYY-MM-DD/daily_master_log.md` (Daily audit record)
- `changes_log/entries/YYYY-MM-DD/change_<ID>_<Timestamp>.md` (Granular entry with before/after diffs & rollback instructions)
- `changes_log/recent_10/` (Rolling FIFO top-10 changes)

**Standardized Timestamps (Universal Rule 8):**
- Filenames: `YYYY-MM-DD_HH-mm-ss`
- Folders: `YYYY-MM-DD`
- Content / Logs: `YYYY-MM-DD HH:mm:ss [TZ]`

### 2.5 Universal Rule 22: temp_prompt/ Phase Execution & Cleanup Management
- **Standard Purpose:** High-complexity architectural tasks and multi-stage feature rollouts must never be implemented as monolithic, untracked changes. They must be partitioned into sequential, verified phases stored in `temp_prompt/<task_or_feature_name>/`.
- **Directory Hierarchy & Layout:**
  - [`temp_prompt/README.md`](file:///c:/Users/Atul%20Verma/Desktop/AI%20Document/Interactive%20Cursor-Tracking%20Portfolio/temp_prompt/README.md): Permanent directory anchor and protocol guide.
  - `temp_prompt/<task_or_feature_name>/INDEX.md`: Master phase orchestration board, subagent assignment matrix, and Definition of Done (DoD).
  - `temp_prompt/<task_or_feature_name>/phase_<NN>_<step_name>.md`: Standalone, granular instruction decks with automated verification scripts.
- **Dedicated Orchestration Subagent (`phase_prompt_architect`):** Dispatched by the CEO (Main Agent) to scaffold phase directories, craft isolated prompt contracts, and track multi-phase execution.
- **Dedicated Skill:** [`phase-prompt-architect`](file:///c:/Users/Atul%20Verma/Desktop/AI%20Document/Interactive%20Cursor-Tracking%20Portfolio/.agents/skills/phase-prompt-architect/SKILL.md) provides complete standards, contracts, and templates for phase decomposition.
- **Ephemeral Lifecycle & Post-Verification Cleanup Protocol:**
  - `temp_prompt/` stores only active, in-flight execution prompts.
  - Upon 100% completion of all phases and **QA Grade A+ signoff** (all test scripts passing with zero errors), the architectural knowledge is permanently committed to [`memory.md`](file:///c:/Users/Atul%20Verma/Desktop/AI%20Document/Interactive%20Cursor-Tracking%20Portfolio/memory.md) and [`docs/FEATURES_MEMORY.md`](file:///c:/Users/Atul%20Verma/Desktop/AI%20Document/Interactive%20Cursor-Tracking%20Portfolio/docs/FEATURES_MEMORY.md), and changes are audited in `changes_log/`.
  - Once synchronized, the ephemeral subfolder `temp_prompt/<task_or_feature_name>/` is **safely deleted/pruned**. The root file [`temp_prompt/README.md`](file:///c:/Users/Atul%20Verma/Desktop/AI%20Document/Interactive%20Cursor-Tracking%20Portfolio/temp_prompt/README.md) remains permanently anchored.
